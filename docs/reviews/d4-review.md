# D4 review: slug-handles (431e6b2)

Verdict: CHANGES NEEDED. These are small fixes. Security is sound. One UI correctness bug can show the wrong status.

## Findings

1. MEDIUM, src/app/submit/PageAddress.tsx:152-197. A stale status shows against a newer slug. `check` is not cleared when `slug` or `url` changes. During the 350 ms debounce, and for good if the fetch fails, the old result is still shown. The "available" branch prints the current `{slug}`. So if the user types a slug that is taken, the page says "claimedfirst.com/artist/<taken> is available" until the reply arrives. `onState` also stays stale, so `blocked` in page.tsx:240 can let the user submit a taken slug or block a free one. The server still catches it (slug_taken), so this does not break the data. Abort-on-cleanup already stops an older response from overwriting a newer one. Fix: store the slug and url the check was made for (`setCheck({...body, for: slug+url})`), and only render or report the state when it matches the current input. Otherwise show a "Checking..." line. Add a vitest test where the user edits the slug after an "available" reply and asserts that the old status is gone.
2. LOW-MEDIUM, src/app/api/submit-check/route.ts:21-50. Anonymous callers have no cost limit. Each call runs an unindexed `ilike '%q%'` scan on artists (two columns) plus an admin-client lookup. The input is capped (slug at 40 chars, url uncapped). The scan is cheap at today's table size, but nothing throttles it. Smallest fix: (a) skip the search when `slug.length < 2`, (b) cap `url` at about 500 chars before parsing, (c) optionally call `rate_limit_hit('check:'||ip, 60, '1 minute')` or rely on Vercel firewall rules. Revisit with a pg_trgm index once the artist count grows.
3. LOW, src/app/api/submit-check/route.ts:31-39. The "listed" lookup uses the service-role client and filters statuses in TypeScript. This is correct: name and slug are returned only for live or pending pages. Pending names are already public through pending_artists_public (0025), and disputed, delisted and removed pages return `listed` with no details. Still, a definer RPC like `artist_link_status(p_key)` would keep the privilege boundary in SQL and avoid using the admin key in an anonymous route. Optional.
4. LOW, migration 0028:402-413 (artist_slug_status). This reveals that a slug exists for disputed, delisted or removed artists (taken=true). It reveals no name, and the user needs this to choose another slug, so it is acceptable and intended. Note: an artist disputed from live is publicly readable under the 0022 policy, but here it is shown without a name. That is conservative and fine.
5. LOW, src/app/submit/page.tsx and PageAddress.tsx (report concern 6). After a successful submit, the "available" message stays on screen. Severity: cosmetic. The next submit of the same link returns "already listed" from the server. Smallest fix: in page.tsx, pass `key={state?.slug ?? "form"}` to PageAddress, or clear `url` when `state?.pending`/success changes. Either one remounts the component and runs the check again, which now shows "listed".
6. LOW, src/lib/artist-url.ts:288-292 and 0028:361-363 (report concern 3). YouTube channel-id slugs look like `channel-ucabcdef123456789ghijk`. They are ugly, and they are truncated and lowercased, so the slug is not a real id. Severity: low. The field is editable and the user is prompted. Smallest fix, mirrored in TS and SQL: drop the `channel-` prefix only when it starts the derived slug, giving `ucabcdef...`. Better: prefill an empty field for `youtube:channel/` keys so the user must choose a slug. Either option needs one test change on each side.
7. LOW, PageAddress.tsx:179-183 (accessibility). The label is correctly linked (`htmlFor="slug"`), the status uses `role="status"` (implicitly aria-live polite), and the input has `aria-describedby="slug-status"`. Two problems: (a) the `claimedfirst.com/artist/` prefix is `aria-hidden`, so screen readers never hear what the field means. Add it to the description, or use visually hidden text in the label. (b) The format hint replaces the status on every keystroke, which makes for chatty announcements. Acceptable once finding 1 is fixed. Keyboard use is fine: it is a plain input, and the links can be reached with Tab.
8. LOW, PageAddress.tsx:145 and artist-url.ts. For a unicode-only handle (`suno:@日本`), `derived` is `""`, not null. The field then renders empty with the format hint, and no fetch is blocked: the fetch still runs and returns invalid_slug. Behaviour is acceptable. Mirror drift: JS `toLowerCase` and Postgres `lower()` can differ on characters such as Turkish İ (JS gives `i̇`, with a combining dot that then becomes `-`). That can change the derived default between the UI and the server when p_slug is null. Not reachable in practice, because the form always sends p_slug when the field is non-empty.
9. INFO, migration 0028 security. Each function is security definer with `set search_path = public, pg_temp`. The old 5-arg submit_artist is dropped, so there is no stale overload. The new 6-arg version is revoked from public, anon and authenticated and granted to service_role. Both new RPCs are revoked from public and granted to anon and authenticated, and return only name and slug. ilike escapes `\`, `%` and `_` with `escape '\'`, and the tests cover it. Everything is parameterized SQL, so there is no injection path. Error mapping covers slug_taken and invalid_slug. Rate limit and promotion logic match 0027 line for line. One gap: no test asserts that `submit_artist(uuid,text,text,text,text)` is gone. Add `hasnt_function('submit_artist', array['uuid','text','text','text','text'])`.
10. INFO, correctness of the race (0028:369-388). Same key and same slug: the second insert blocks on the slug unique index until the first commits, then finds the link and becomes the same artist. Same key with different explicit slugs: both artist inserts succeed, the second link insert hits unique_violation, and its own artist row is deleted and replaced. Different key with the same slug: slug_taken. When the key is already listed, p_slug and the name are ignored. This is all correct. submit_concurrency.sh reportedly passes.
11. INFO, tests. The pgTAP tests are meaningful (64 tests, real behaviour, grants, search_path, columns, escaping, limit). The vitest tests cover empty, available, taken, listed, debounce, bad format, form name and re-derive. Missing: the stale-status case (finding 1), and a test where an older response arrives after a newer one.

## Browser check
At desktop size, /submit shows the Page address row once a link is pasted. With a channel-id link it prefilled `channel-ucabcdef123456789ghijk`. At 375px the prefix wraps above the input, and scrollWidth equals the viewport width (375), so there is no horizontal overflow. I reset the viewport to desktop afterwards.
